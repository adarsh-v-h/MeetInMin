# MeetInMin MVP: Progress & Roadmap

_Last updated: October 2026_

---

## ✅ What We Have Built So Far

### 1. Backend Architecture & Security
- **FastAPI Foundation:** Async-first Python API, structured with versioned routers (`/v1`).
- **Database Models (SQLAlchemy):** Normalized schema covering:
  - `User` — core identity, Argon2 hashed passwords, Google OAuth tokens.
  - `APIKey` — multiple revokable extension credentials per user.
  - `Meeting` — audio upload records with lifecycle status tracking.
  - `Transcript` — raw STT output stored as source of truth.
  - `MeetingInsight` — executive summary generated by GLM.
  - `ActionItem` — extracted action items with assignees.
  - `KeyDecision` — key decisions from the meeting.
  - `EmailContextSource` — attribution records for emails used as context (new).
- **Cryptographic Security:**
  - **Argon2** (via CFFI) in a non-blocking threadpool for password hashing.
  - **JWT** for stateless frontend sessions.
  - **SHA-256** hashing for API Key verification.

### 2. Authentication Engine
- **Manual Registration & Login:** `POST /register`, `POST /login` — supports username or email login.
- **Google OAuth 2.0:**
  - `GET /login/google` — redirects to Google consent screen (requests Gmail read-only scope).
  - `GET /login/google/callback` — exchanges authorization codes, stores `google_refresh_token`.
  - `POST /complete-profile` — forces Google-auth users to pick a unique username.

### 3. Chrome Extension Bridge
- **API Key Generation:** `POST /generate-api-key` — spawns secure per-device credentials.
- **Audio Ingestion API:** `POST /meetings/upload/{api_key}` — accepts large `.webm` audio files via:
  - `aiofiles` async 1MB chunked writes.
  - Auto-generated collision-proof filenames (`username_uuid_timestamp.webm`).
  - Instantaneous SHA-256 API Key verification.
- **MeetInMin Extension:** Rebranded Chrome extension, distributed from the Landing page.

### 4. Zoho AI Pipeline (STT + GLM)
- **Zoho Catalyst Zia STT:** Audio is automatically converted to 16kHz mono WAV using `pydub`/`ffmpeg` before being sent to Zoho's Speech-to-Text endpoint. Raw transcript is stored in the DB before any further processing.
- **Zoho GLM (`crm-di-glm47b_30b_it`):** Structured meeting intelligence extraction producing:
  - Executive Summary
  - Action Items (with assignees)
  - Key Decisions
- **Retry Logic:** Both STT and GLM calls implement exponential backoff with jitter for resilience.
- **Background Processing:** Audio analysis runs in an async background task, with meeting status tracked through `transcribing → analyzing → completed / failed`.

### 5. Gmail Context Enrichment Pipeline
- **Automatic trigger:** Fires automatically after transcription when a user has a connected Gmail account.
- **Keyword extraction:** A lightweight GLM call on the transcript extracts domain-specific keywords (project names, people, topics) to use as Gmail search terms.
- **Gmail API client:** Exchanges the user's `google_refresh_token` for a short-lived access token; searches Gmail for relevant emails within a configurable date window; fetches full MIME message bodies with HTML stripping.
- **Context injection:** Relevant email snippets are assembled into a structured context block and injected into the main GLM prompt as supplementary context. The transcript always remains the primary source — emails only fill gaps.
- **Attribution storage:** Only metadata is persisted (`EmailContextSource` model): `gmail_message_id`, subject, sender, received date, and a short snippet. Raw email bodies are never stored.
- **Fail-safe:** If Gmail fails at any step, the system logs a warning and proceeds with transcript-only analysis. The meeting record never fails due to a Gmail error.

### 6. Web Dashboard (Frontend — React + Vite)
- **Auth UI:** Glassmorphism Login, Register, and Landing pages.
- **AppShell:** Persistent collapsible sidebar with `lucide-react` iconography.
- **API Keys (`/api-keys`):** Full lifecycle — creation, one-time secret display, revocation, status badges.
- **Dashboard (`/dashboard`):** Paginated meeting list with pulsing animated processing status.
- **Meeting Details (`/meetings/:id`):**
  - Executive Summary, Action Items, Key Decisions panels.
  - Raw Transcript panel with copy-to-clipboard.
  - **Email Context Sources section:** Displays which emails were used to enrich the analysis, each with an "Open in Gmail" link.
  - **Gmail Nudge Banner:** Shown for completed meetings where no Gmail context was available — gently prompts the user to connect Gmail for better results (no gating, baseline results always shown).
  - Audio download support.
- **Settings (`/settings`):** Google account connection/disconnection, profile management.

## 🗺️ What Is Left To Build

### Phase 1: Polish & Stability
- [ ] **Migrate to PostgreSQL** — swap SQLite for a production-grade database (connection string change only, schema is already abstracted).
- [ ] **Rate limiting & auth hardening** — add per-API-key request rate limits.
- [ ] **Error boundary UI** — graceful frontend fallbacks for network errors.

### Phase 2: Chrome Extension Polish
- [ ] **API Key input in popup** — allow users to paste their key directly in the extension.
- [ ] **Upload feedback** — show progress / success / failure state in the extension popup after audio is sent.

### Phase 3: Gmail — Phase 2 (Future)
- [ ] **"Send Reply" button** (Frontend only, Coming Soon) — button exists in the UI, but is disabled with a tooltip. No backend logic yet.
- [ ] **Email-based meeting correlation** — link related meetings that share the same email thread.

### Phase 4: Product Expansion
- [ ] **Merge Meetings** — merge multiple recordings of the same call into one insight (UI placeholder already exists).
- [ ] **Team / Org support** — share meeting summaries with teammates.
- [ ] **Notification integrations** — Slack / Teams webhooks for action item delivery.

## 🏗️ Tech Stack Summary

| Layer | Technology |
|---|---|
| Backend API | FastAPI (Python, async) |
| Database ORM | SQLAlchemy 2.0 (SQLite → PostgreSQL) |
| Password Hashing | Argon2 via CFFI |
| Auth | JWT + Google OAuth 2.0 |
| Speech-to-Text | Zoho Catalyst Zia STT |
| Meeting Intelligence | Zoho GLM (`crm-di-glm47b_30b_it`) |
| Email Enrichment | Gmail API (OAuth, read-only) |
| Frontend | React + Vite + Vanilla CSS |
| Chrome Extension | Manifest V3, Offscreen Documents |
